# NCIG v0.14 — real architecture catalog

The machine-local `ncig-harvest-v1` is intentionally broad: it contains resource paths from meshes, entities and materials plus source metadata. The architecture catalog is a compact derived index for procedural shell assembly.

## Command

```powershell
python -m ncig.cli architecture-catalog `
  --harvest build/user_harvest/harvest.json `
  --out build/architecture_catalog.json `
  --interior-only
```

`--interior-only` keeps architecture that appears to belong to interior kits (`common\int`, explicit `interior` path segments, and related interior filename signals). Remove it to retain exterior architecture as fallback.

## Candidate classes

`floor_piece`, `wall_piece`, `ceiling_piece`, `door_frame`, `door_piece`, `opening_piece`, `window_piece`, `pillar_piece`, `stairs_piece`, `rail_piece`, `trim_piece`.

The catalog excludes character/vehicle/weapon/UI domains even if a path contains a structural-looking word. `.ent` files are not treated as structural mesh candidates by this catalog.

## Dimensions

Names such as `wall_l600_w300_h300.mesh` are parsed as centimetre hints and exposed in both centimetres and metres. They are labelled `source=filename_hint`; they are never treated as authoritative mesh bounds.

## Native export boundary

The catalog chooses real resource paths only. It does not manufacture the runtime-sensitive enum fields of a `worldMeshNode`. A clean native Object Spawner export still requires a verified node template from the installed World Builder/entSpawner toolchain.
