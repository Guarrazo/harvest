# NCIG v0.3 — Object Spawner bridge

NCIG now has a **template-driven bridge** instead of guessing the exact JSON schema emitted by a user's World Builder build.

## Why this is necessary

World Builder is the authoring layer and its exported JSON is consumed by WolvenKit's `import_object_spawner` script. The documented workflow is: export a group from World Builder, put the JSON in a WolvenKit project's `raw` folder, then run the system `import_object_spawner` script. The script creates an `all.streamingBlock` plus a `sectors` folder containing the streaming sector(s).

NCIG therefore does not fabricate a CR2W schema. It learns the node envelope from one real export and fills it with NCIG-generated nodes.

## One-time user action required

1. In Cyberpunk, open World Builder.
2. Spawn one simple object that is known to export correctly (a vanilla mesh or entity is ideal).
3. Put it in a group, e.g. `ncig_probe`.
4. Save the group and add it to Export.
5. Export it.
6. Locate:
   `Cyberpunk 2077\\bin\\x64\\plugins\\cyber_engine_tweaks\\mods\\entSpawner\\export\\ncig_probe_exported.json`
7. Copy that JSON into the NCIG project as `examples/ncig_probe_exported.json`.

The probe does **not** need to be a special asset and does not modify the game. Its only purpose is to give NCIG the exact JSON envelope used by the installed World Builder build.

## Inspect it

```powershell
python -m ncig fingerprint --input examples/ncig_probe_exported.json --out build/probe_fingerprint.json
```

## Bridge an NCIG plan

```powershell
python -m ncig bridge `
  --plan build/v02_demo/generated/wb_plans/demo_shop_001_world_plan_v2.json `
  --template examples/ncig_probe_exported.json `
  --out build/demo_shop_001_object_spawner.json
```

The result intentionally remains an Object Spawner export JSON. WolvenKit remains responsible for converting that export into native `streamingsector` / `streamingblock` resources, following the documented import workflow.

## Safety rule

NCIG never silently claims a native export when the exact template has not been supplied. Unknown node types are reported as warnings rather than being represented as invented CR2W fields.
