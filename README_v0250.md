# NCIG v0.25.0 — exact collision probe

v0.25.0 adds a read-only diagnostic stage for the `worldCollisionNode` removal evidence generated by v0.24.0.

## What it does

`src/ncig/collision_probe.py` takes `build\collision_removal_manifest.json`, resolves each target against the user's local `.streamingsector.json` export, and reports:

- exact `node_index` and `expectedNodes` integrity;
- the exact target node type/name/resource;
- the target's matching `nodeData` placement entries;
- best-effort collision shape information using the same parser as the physics index;
- nearby mesh/proxy/collision nodes and their distances/types;
- a compact diagnostic suitable for deciding whether the target is a real doorway blocker.

The probe never rewrites the source sector and never deletes anything.

## First test

Run:

```text
.\tools\probe_collision_manifest_cp2077.cmd build\collision_removal_manifest.json C:\CyberpunkExports\sectors build\collision_probes.json auto_11424_commercial 1 --safe-only
```

This selects the first clean high-confidence building from the v0.24 manifest: `auto_11424_commercial`, node 206 in `exterior_41_4_1_0.streamingsector`, which was marked `safe_to_auto_remove: true` by the v0.24 audit.

The console prints a small summary. The full report is written to `build\collision_probes.json`.

The full v0.24/v0.25 preparation pipeline also creates `build\collision_probe_first_safe.json` automatically for the first `safe_to_auto_remove` target. When the exported sector contains an unambiguous depot-style streamingsector path, it additionally writes `build\collision_probe_first_safe.archive.xl` as a **review-only draft**; NCIG never installs or activates it.

To inspect more safe targets:

```text
.\tools\probe_collision_manifest_cp2077.cmd build\collision_removal_manifest.json C:\CyberpunkExports\sectors build\collision_probes_safe.json "" 10 --safe-only
```

## Why this stage exists

v0.24 identifies collision nodes that overlap detected exterior doors, but that is evidence rather than proof of walkability impact. v0.25 bridges the offline sector export and the exact node payload before any ArchiveXL/removal automation is attempted.

Do not mass-delete these nodes based only on the manifest. Runtime validation should first establish that the target is the blocking object and that no embedded mesh collision remains.


## ArchiveXL handoff

The probe recovers embedded `*.streamingsector` path strings when the export preserves them. When one or more unambiguous paths are found, the report contains `archive_xl_fragment` for each target and `--xl-out` can emit a grouped draft using `expectedNodes` plus each target node index/type. This follows the documented Removal Editor/ArchiveXL deletion structure, but the generated file remains a draft until runtime verification confirms the collider is actually blocking the entrance.
