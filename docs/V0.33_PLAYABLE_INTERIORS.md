# NCIG v0.33 — Playable interior pipeline

NCIG v0.33 changes the native-output strategy so a real World Builder mesh template is optional rather than a hard dependency.

## Goal

1. Detect an exterior structure with a likely entrance and no convincing interior.
2. Use the footprint, floors, entrance and structural layout to generate a room graph and architecture.
3. Materialize static meshes with the public entSpawner World Builder export schema.
4. Materialize collisions from the existing NCIG collision serializer.
5. Materialize real harvested .ent decoration where available.
6. Add a worldTriggerAreaNode with a worldInteriorAreaNotifier for each generated floor.
7. Emit the result as custom streaming sectors for WolvenKit/ArchiveXL integration.

A harvested real worldMeshNode remains useful as an optional validation/reference source, but it is no longer required to construct the building.

## Why this abstraction

World Builder maps object categories to native worldNode types. Static Mesh is worldMeshNode, collision is worldCollisionNode, Entity Template is worldEntityNode, and an Interior Trigger is worldTriggerAreaNode. The exporter source also exposes the JSON shape used for these nodes.

NCIG therefore keeps building semantics separate from native node serialization. This makes the generator easier to scale from one demo building to automated city-wide interior filling.

## Current demo target

- auto_10712_industrial
- existing v0.28 structural output
- existing architecture assembly
- existing real .ent decoration harvest
- examples/ncig_probe_exported.json as the Object Spawner envelope

The launcher does not rerun the detector or structural generation.

## Remaining validation

The software audit validates node structure, resources and transforms. The final validation is still WolvenKit import and an in-game test.

Later versions will add stronger facade-opening fitting, adaptive irregular footprints, lighting/reflection probes, proxy/occluder strategy and optional NPC/community/navigation data.
