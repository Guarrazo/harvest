# NCIG v0.13 — preflight and user harvest

v0.13 adds an export gate between procedural generation and native Object Spawner output.

## First task on a real Cyberpunk installation

Run from the NCIG project root in PowerShell:

```powershell
.\tools\harvest_cp2077.ps1
```

The helper assumes the user's current game root is `F:\Games\CP2077\Cyberpunk 2077` and harvests:

```text
bin\x64\plugins\entSpawner
```

It writes:

```text
build\user_harvest\harvest.json
build\user_harvest\templates.json
```

To use a different game root:

```powershell
.\tools\harvest_cp2077.ps1 -GameRoot "D:\Games\Cyberpunk 2077"
```

Do not edit either JSON by hand. The important data is the real node templates and resource paths found on that machine.

## After harvesting

Generate the first test building:

```powershell
$env:PYTHONPATH="$PWD\src"
python -m ncig.cli generate --input examples\buildings.json --out build\generated --playable-shell
```

Then run the export gate:

```powershell
python -m ncig.cli preflight `
  --plan build\generated\wb_plans\demo_shop_001_world_plan_v2.json `
  --assets build\user_harvest\harvest.json `
  --templates build\user_harvest\templates.json `
  --base examples\ncig_probe_exported.json `
  --out build\preflight.json
```

`ready: true` means the plan has no known NCIG-side template/resource blockers. It does not claim that Cyberpunk or WolvenKit has accepted the export yet.

## Return artifact

For the next development step, send back the two files:

```text
build\user_harvest\harvest.json
build\user_harvest\templates.json
```

A zip containing the `build\user_harvest` folder is also fine.
