# NCIG v0.10 — floor-safe composition and connectivity

NCIG v0.10 hardens the multi-floor pipeline before the first real in-game building test.

## 1. Explicit floor ownership

Every node in `ncig-world-plan-v3` now carries a `floor` integer. Every generated sector also carries its floor in the planning representation.

The schema bridge filters nodes by this field. A node authored for floor 2 is no longer emitted into floor 1 or floor 3 sectors.

## 2. Connectivity graph

Each world plan now contains `connectivity` with:

- an entrance node;
- room door/activity nodes;
- one vertical-core node per floor;
- bidirectional room/corridor links;
- bidirectional vertical transitions between consecutive floors.

This graph is an NCIG planner/runtime contract. It is **not** a native navigation mesh and does not claim to create AI navigation by itself.

## 3. Plan lint

Run:

```powershell
python -m ncig.cli plan-lint `
  --plan build/generated/wb_plans/demo_megabuilding_001_world_plan_v2.json `
  --out build/plan_lint.json
```

The linter checks:

- sectors exist and have extents;
- sector names are unique;
- every node has a unique `nodeRef`;
- every node has an explicit floor;
- every node floor has a matching sector.

## 4. Native diagnostics

The native bridge report now records emitted node counts per sector. This makes it possible to compare the generated distribution with the expected floor partition before importing the JSON into WolvenKit.
