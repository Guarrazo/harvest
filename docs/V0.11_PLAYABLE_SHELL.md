# NCIG v0.11 — playable-shell composition

v0.11 moves the project from "procedural room plan" toward a first in-game shell without pretending to know runtime-sensitive values that have not been verified.

## What changed

- Room shell node rotations now include the building yaw, so rotated buildings keep walls/meshes aligned with their footprint.
- `playable_shell` adds one explicit `worldAreaShapeNode` per generated room, using the generated room footprint as the area outline.
- Collision specs can be generated for floors and non-opening wall segments when the exact collision `preset` and `material` are supplied.
- Harvested mesh templates now accept generated resource/appearance overrides while retaining their real render-profile fields.
- Harvested collision templates now accept generated box size/preset/material overrides without replacing the exporter-specific surrounding payload.
- Harvested light templates now accept explicit plan light-profile overrides without discarding harvested enum defaults.

## Command

```powershell
$env:PYTHONPATH="$PWD/src"
python -m ncig.cli generate `
  --input examples/buildings.json `
  --out build/v011_demo `
  --playable-shell
```

For physical collision nodes, pass exact values already verified in your World Builder/export workflow:

```powershell
python -m ncig.cli generate `
  --input examples/buildings.json `
  --out build/v011_demo `
  --playable-shell `
  --collision-preset "<verified preset>" `
  --collision-material "<verified material>"
```

Without those values NCIG still emits room areas and a shell diagnostic, but deliberately does not invent collision enums/materials.

## Runtime boundary

`worldAreaShapeNode` is an exported area-shape node, not a claim that AI navigation, door logic or encounter systems are already fully wired. The shell is a deterministic intermediate artifact for the native bridge.
