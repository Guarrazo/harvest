# NCIG v0.32 — automatic native template discovery

The native stage no longer requires a separately prepared World Builder mesh probe.

NCIG now searches the exported \`streamingsector\` JSON directory for a real \`worldMeshNode\` payload. Existing remote templates are merged when available. If no usable mesh node can be found, NCIG uses the known reference serializer as an explicit fallback and records that fact.

The native test launcher can now be run with no arguments:

~~~cmd
.\tools\continue_native_pipeline_cp2077.cmd
~~~

It uses:

- \`C:\CyberpunkExports\sectors\` for real world-node templates.
- \`examples\ncig_probe_exported.json\` as the envelope base when no explicit World Builder export is supplied.
- \`auto_10712_industrial\` as the first target.
- The existing v0.28 structural layouts and architecture assembly.
- Real .ent decoration when the remote harvest is present.

An explicit World Builder/Object Spawner export may still be supplied as the first argument; it is then used as the base envelope and its node templates are merged too.

The final physical validation remains WolvenKit import and an in-game test.
