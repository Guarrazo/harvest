# NCIG v0.22.7 — city-scale world export pipeline

## Purpose

v0.22.7 prepares NCIG for a large local export of Night City's compiled/default world sectors.

The city detector is separate from the original small detector so the large-world path can evolve without destabilizing the established building-generation pipeline.

## Input

Use a local directory containing the JSON-converted `.streamingsector` files from the base-game world export, for example:

`C:\CyberpunkExports\sectors`

The loader accepts:

- World Builder/Object Spawner envelopes containing a `sectors` array.
- A direct single-sector JSON with `nodes`.
- A direct single-sector export with `nodes` plus `nodeData` placements.

## City-scale detection

The detector builds an XY spatial grid for:

- entrance clustering;
- nearby exterior architecture lookup;
- existing interior evidence lookup.

This avoids a full pairwise scan of every world node against every entrance.

Existing-interior evidence is tested against the candidate's estimated oriented footprint with a small margin. An interior belonging to a nearby building therefore has less chance of incorrectly suppressing an otherwise valid exterior candidate.

## Outputs

The preparation script writes:

- `build\world_manifest.json` — export inventory and parse health.
- `build\auto_building_candidates.json` — all detected candidates and evidence.
- `build\auto_buildings.json` — selected candidates for generation.
- `build\generated_auto\layouts.json` — generated layouts.
- `build\real_architecture_remote\architecture_assembly_auto.json` — real-asset architecture assembly.

## Recommended workflow

1. Convert/export the complete desired `default` sector tree to JSON once.
2. Keep that data in the local workspace; do not commit it to the public NCIG repository.
3. Run:

```powershell
.\tools\prepare_detected_buildings_remote.cmd https://github.com/Guarrazo/harvest C:\CyberpunkExports\sectors 10
```

The last argument is still a safety cap on generated anchors. The city detector itself analyzes every JSON file under the supplied directory.

The first diagnostic to inspect is `build\world_manifest.json`. If its file/record counts are sensible, inspect `build\auto_building_candidates.json` before increasing the generation cap.
