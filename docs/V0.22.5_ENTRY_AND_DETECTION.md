# NCIG v0.22.5 — walkable entries and detected building targets

## Collision orientation

The generated room door is on the corridor-facing wall:

- positive-Y rooms: north wall
- negative-Y rooms: south wall

v0.22.5 fixes the previous inversion that opened the exterior wall instead. The continuous floor collision remains, while the corridor wall keeps a centered doorway gap.

A detected exterior entrance creates a second opening on the facade that contains the detected entry. Its collision is split around the same opening.

## Door leaves

A structural `door_piece` mesh is not emitted unless the catalog explicitly marks it as collisionless. This prevents a static door mesh from blocking a doorway that the generator intends to be traversable. Door frames can still be emitted around the opening.

## Thin wall rendering

Many CP77 architectural pieces are very thin planar meshes. When runtime bounds show a wall thickness of 8 cm or less, NCIG emits a second copy rotated 180 degrees with a small offset. This is intended to provide a visible reverse face for interiors without duplicating ordinary thick walls.

## Automatic building detection

`detect-buildings` now keeps node yaw, scale and filename `l/w/h` hints while scanning exported streamingsector JSON. Entrance groups seed candidates; nearby exterior architecture supplies a geometry-aware footprint and PCA-derived building orientation.

Candidates now carry:

- exterior footprint estimate and height/floor estimate
- detected entrance world position
- local entry position relative to the generated building
- entry side and outward-facing angle
- estimated real entrance width/height when encoded by the resource filename
- source sectors/files used as evidence

The automatic preparation helper prefers `architecture_catalog_bounded.json` when the 1,579-resource runtime-bounds catalog has already been produced.

## Current scope

Detection is still evidence-based rather than a claim that every facade is empty. The intended next iteration is to use the detected exterior shell itself as the authoritative footprint, then validate entrance-to-interior alignment against the actual exported world geometry before composing the native Object Spawner result.
