# NCIG v0.17 — Remote harvest cache

NCIG can now consume a public GitHub repository containing a machine-local harvest without requiring the large `harvest.json` to be copied through the chat interface.

## Direct command

```powershell
$env:PYTHONPATH="$PWD/src"
python -m ncig.cli sync-harvest --source https://github.com/Guarrazo/harvest --out build/remote_harvest
```

The cache contains `harvest.json`, `templates.json`, and, when available, `architecture_catalog.json` and `architecture_assembly.json`, plus `manifest.json`.

## Windows helper

```powershell
.\tools\sync_harvest_github.cmd https://github.com/Guarrazo/harvest
```

## Prepare architecture from the remote cache

```powershell
.\tools\prepare_architecture_remote.cmd https://github.com/Guarrazo/harvest
```

The helper downloads the harvest to `build/remote_harvest`, generates a demo layout only when no generated layout exists, builds the compact architecture catalog, and assembles it.

### Trust and safety boundary

The sync layer is intentionally conservative:

- It accepts public GitHub repository URLs only.
- It limits individual downloads to 80 MB.
- Downloads are written atomically to avoid leaving partial JSON in the cache.
- Every downloaded file is recorded with byte count and SHA-256 in `manifest.json`.
- Optional architecture artifacts are allowed to be missing; required `harvest.json` and `templates.json` are not.
- NCIG does not execute code from the remote repository.
