# NCIG v0.20 — target detection, coherent architecture kits, runtime bounds

## What changed

The architecture assembler no longer intentionally mixes unrelated structural families for every wall/floor/ceiling/door. It selects one dominant architecture family per building and only falls back when that family has no member for a required class.

The structural classifier now gives explicit filename semantics priority over broad harvest roles. This prevents resources such as `*_ceiling_tiles_*` from being treated as floor pieces just because the generic harvester also noticed the word `tile`.

`detect-buildings` analyzes exported `.streamingsector` JSON files. Entrances seed spatial candidates; nearby architecture nodes form the building footprint. Existing interior evidence lowers the candidate confidence rather than being treated as proof that an interior is missing.

`candidates-to-buildings` converts high-confidence candidates into the exact `buildings.json` input accepted by the generator, including a PCA-derived yaw and estimated footprint.

`bounds-targets` creates the mesh list used by the optional CET runtime bounds harvester. `NCIGBoundsHarvester` loads the real `.mesh` resources through the same ResourceDepot/EntityBuilder path used by entSpawner and records the runtime bounding box. `merge-bounds` enriches the architecture catalog with these measurements. The native preparation helper automatically reuses the bounded catalog when present.

## Detection evidence boundary

Automatic detection is deliberately a candidate generator, not a claim that every candidate is a decorative facade. The base game stores world content in streaming sectors, and tools such as WolvenKit expose the sector/block relationship for analysis. Use a clean export of the game's relevant sectors as the input to `detect-buildings`.

## Runtime bounds workflow

1. Generate the targets:

```powershell
python -m ncig.cli bounds-targets --catalog build\real_architecture_remote\architecture_catalog.json --out build\real_architecture_remote\architecture_bounds_targets.json
```

2. Install the CET harvester:

```powershell
.\tools\install_bounds_harvester.cmd
```

3. Start Cyberpunk and leave CET active until the log reports completion.

4. Merge the resulting bounds:

```powershell
.\tools\merge_bounds_cp2077.cmd
```

The merged catalog is `architecture_catalog_bounded.json`. A subsequent native preparation run uses it automatically.

## Automatic building detection workflow

Export the relevant base-game streamingsector files as JSON, place them in one directory, then run:

```powershell
.\tools\prepare_detected_buildings_remote.cmd https://github.com/Guarrazo/harvest C:\CyberpunkExports\sectors 10
```

This produces a scored candidate report and a selected `auto_buildings.json`. It is intentionally separate from the native exporter so candidates can be inspected before anything is written into the game.
